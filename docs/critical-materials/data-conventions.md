# Critical Materials Intelligence — Data Conventions

Locked decisions from the *Critical Materials Implementation Direction* guidance.
These conventions apply across the website, seed data and backend. Deviating
from them requires updating this document first.

## 1. Rare-earth classification convention (P0-14)

GeoMoney adopts the **USGS Mineral Commodity Summaries** split:

| Group | Members |
|---|---|
| Light Rare Earth (LREE) | La, Ce, Pr, Nd, Sm, Eu, **Gd** |
| Heavy Rare Earth (HREE) | Tb, Dy, Ho, Er, Tm, Yb, Lu, **plus Yttrium (Y)** |
| Scandium (Sc) | Classified separately — `Rare Earth (Scandium)` — never casually grouped with LREE/HREE |

Corrections applied to the seed data (`src/data/critical-materials.ts`):

- **Europium**: `Rare Earth` → `Light Rare Earth`
- **Gadolinium**: `Heavy Rare Earth` → `Light Rare Earth` (Gd closes the LREE block under the USGS convention)
- **Yttrium**: remains `Heavy Rare Earth` (deliberately grouped with the HREEs per USGS, although it is not a lanthanide)
- **Scandium**: `Rare Earth` → `Rare Earth (Scandium)`

## 2. Element symbols vs commercial products (P0-14)

- The `symbol` field is always the **chemical element symbol**.
- **Uranium = `U`**. `U3O8` is a commercial uranium-oxide reference product and
  belongs in the price-benchmark layer (`PriceBenchmark.productForm`), never in `symbol`.
- **Natural Graphite = `C`** and remains distinct from any future synthetic-graphite
  material entry (which would get its own `materialKey`, e.g. `mat_synthetic_graphite`).

## 3. Permanent material keys (P0-16)

Every material has a permanent, display-name-independent key:

```
mat_<lowercase_name_with_underscores>
```

Examples: `mat_gallium`, `mat_thulium`, `mat_natural_graphite`, `mat_uranium`.

- Generated by `toMaterialKey()` in `src/lib/material-intel-service.ts`.
- Stored on `RareEarthMaterial.materialKey` (unique).
- Watchlists, price history, events, alerts, user preferences and URLs must key
  off `materialKey`/row `id`, never off the display name.

## 4. Category vs backend taxonomy (P0-15)

- `category` remains the visible card label only. It currently mixes chemical
  families with end-use applications and must not become the material's single identity.
- Backend concepts live in separate fields: `materialFamily`,
  `applicationTags` (JSON array), `strategicTags` (JSON array).

## 5. Countries by supply-chain stage (F3)

`MaterialCountryRole.stage` uses this controlled vocabulary:

| Stage | Meaning |
|---|---|
| `mining` | Mine / primary production |
| `refining` | Refining / separation |
| `processing` | Processing / conversion / separation |
| `manufacturing` | Component / material manufacturing |
| `consumption` | Major consuming market |

One country may appear in several stages. `sharePct` + `dataYear` + `sourceId`
must be populated whenever a percentage is shown — no hard-coded unattributed
percentages in page copy.

## 6. Structured application relationships (F2)

`MaterialApplication` fields:

- `relationship`: `direct_use` | `compound` | `downstream_technology` | `sector`
- `strength`: `direct` | `strong` | `moderate` | `weak`
- `qualifiesWithoutMention`: whether an article can qualify for the material
  without explicitly naming it.

Rule: broad sectors (e.g. "electronics", "medical lasers", "defence optics")
must be `weak`/`sector` with `qualifiesWithoutMention = false`. Only direct or
strong relationships with an evidenced material linkage may qualify an article
when the material is not named (P0-4/P0-5).

## 7. Price architecture (F5, P0-10/P0-11)

Three layers — never `material -> unit -> current price`:

1. `RareEarthMaterial` — permanent material information.
2. `PriceBenchmark` — what is being priced: `productForm`, `grade`,
   `benchmarkName`, `market`, `currency`, `unit`, `updateFrequency`, `sourceId`.
3. `PriceObservation` — append-only timestamped values, unique per
   `(benchmarkId, asOf)`. Pages query the newest valid observation.

Examples:

- Uranium → benchmark `U3O8`, unit `lb`
- Lithium → benchmark `lithium carbonate`, grade `battery grade`, unit `tonne`;
  separate benchmark `lithium hydroxide`, unit `tonne`
- Dysprosium → benchmark `dysprosium oxide`, grade `99%+`, unit `kg`

## 8. Source provenance (F4, P0-12/P0-13)

A `Source` record stores: `publisher`, `document`, `url`, `publicationDate`,
`dataYear` (the year the data describes — stored separately from the
publication year), `retrievedAt`, `verifiedAt`. Generic references such as
"USGS MCS 2025" are a display-layer starting point only, not the permanent
source model. Before duplicating data across back pages, check whether a newer
authoritative edition exists; retain older sources when they remain the best
or original authority.

## 9. Seed behaviour

`POST /api/rare-earth` matches existing rows by `materialKey`, then `symbol`,
then `name`, and updates in place. This means taxonomy/symbol corrections
(e.g. Uranium `U3O8` → `U`) never orphan watchlist rows or create duplicates.
